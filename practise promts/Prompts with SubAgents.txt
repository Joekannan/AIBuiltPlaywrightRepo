PART 1 — AGENT ECOSYSTEM
──────────────────────────────────────────────
Build the following agents in .github/agents/:

┌─────────────────────────────────────────────────────────────┐
│  ORCHESTRATOR  playwright-qa.agent.md                       │
│  user-invocable: true                                       │
│  tools: [agent, todo]   ← NO file editing, NO terminal      │
│  Job: classify user intent → delegate to the right          │
│       sub-agent(s) in sequence → report final result        │
└─────────────────────────────────────────────────────────────┘
         │
         ├──► pom-builder.agent.md
         │     user-invocable: false
         │     tools: [read, edit, search]
         │     Job: create/update page objects and fixtures ONLY
         │     Reads: page-objects.instructions.md
         │
         ├──► spec-writer.agent.md
         │     user-invocable: false
         │     tools: [read, edit, search]
         │     Job: write E2E spec files and API test files ONLY
         │     Reads: test-patterns.instructions.md,
         │            api-testing.instructions.md
         │
         ├──► test-runner.agent.md
         │     user-invocable: false
         │     tools: [execute, read]
         │     Job: run playwright/bddgen commands, capture output ONLY
         │     Returns: pass/fail counts + raw error messages
         │
         ├──► failure-fixer.agent.md
         │     user-invocable: false
         │     tools: [read, edit, search]
         │     Job: diagnose errors from test-runner output,
         │          apply fixes to page objects or specs ONLY
         │     Reads: test-patterns.instructions.md,
         │            page-objects.instructions.md
         │
         └──► ci-updater.agent.md
               user-invocable: false
               tools: [read, edit]
               Job: update .github/workflows/ files ONLY
               Reads: ci-cd.instructions.md

ORCHESTRATION SEQUENCES the orchestrator must follow:

  "add [feature] test"
    → pom-builder → spec-writer → test-runner
      → (if failures) failure-fixer → test-runner

  "run tests" / "fix failing tests"
    → test-runner → (if failures) failure-fixer → test-runner

  "scaffold framework"
    → pom-builder → spec-writer → test-runner
      → (if failures) failure-fixer → ci-updater

  "update ci" / "github actions"
    → ci-updater

AGENT COMMUNICATION RULES:
- Orchestrator passes EXPLICIT context to each sub-agent:
  file paths created/modified by previous step, error messages,
  feature name, page object names already available
- Sub-agents return a single structured message:
  { status: "done|failed", files: [...], errors: [...], summary: "..." }
- Orchestrator interprets that output before calling the next sub-agent
- Sub-agents NEVER call each other directly
